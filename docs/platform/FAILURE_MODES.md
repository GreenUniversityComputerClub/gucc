# Failure modes

What each part does when something it depends on fails. The tests named in the last column
inject the failure and check the behaviour (`tests/integration/failure-modes.test.ts` unless
noted).

| Failure                                                              | What people see                                                                                                                                            | What the system does                                                                                                                                                                                                  | Tested by                                                            |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| **D1 (database) down or failing**                                    | Public pages keep showing from Vercel's cache (ISR). The dashboard shows "Something went wrong. Reference: …"; forms say so instead of pretending to save. | The API answers `500` with a reference id and no internals; `/health` answers `503`; the error is written to `error_events` when the database is reachable again (never throws).                                      | "database unavailable"                                               |
| **R2 (file storage) down**                                           | Images don't load until it's back; uploads say they failed.                                                                                                | `/media/*` answers `503` with `Retry-After: 30`, never cached. An upload that fails to write gives back its reserved allowance, and its half-written objects are deleted.                                             | "file storage unavailable"; `free-tier.test.ts` (release on failure) |
| **Resend (email) down or refusing**                                  | The action still completes. Where email would have carried a link (invitations, resets), the dashboard shows the link to share instead.                    | `email_log` records `failed` with Resend's answer (or "couldn't be reached"); the day's allowance is given back. Notification copies are simply not sent; the in-app notice exists regardless.                        | "email service unavailable"; `email-outbox.test.ts`                  |
| **Worker (API) down**                                                | Public pages from cache; the dashboard can't load data and says so.                                                                                        | Nothing to do in code; Cloudflare restarts Workers. A deploy that breaks the Worker is rolled back automatically by the release (smoke test).                                                                         | `scripts/platform/release.ts` step 5                                 |
| **Workers free limit reached** (100,000 requests/day)                | API calls fail until 00:00 UTC; public pages from cache.                                                                                                   | Nothing is charged on Workers Free.                                                                                                                                                                                   | —                                                                    |
| **Vercel down or paused** (Hobby limit reached)                      | The site is unavailable.                                                                                                                                   | Out of our control; nothing is charged. The API keeps running.                                                                                                                                                        | —                                                                    |
| **Session expired or revoked**                                       | Sent to sign-in, then back to the page.                                                                                                                    | The API answers `AUTH_REQUIRED`; pages redirect. Sensitive accounts are signed out after 12 idle hours.                                                                                                               | `security-v4.test.ts`                                                |
| **Website newer or older than the API** (mid-deploy)                 | Leaders see "The API is a different version"; a page the older API can't serve says "Not available yet" instead of crashing.                               | Responses are checked against the contract and missing fields get safe defaults; unknown procedures answer `UNKNOWN_PROCEDURE`.                                                                                       | `api-contract.test.ts`, `edge-idempotency.test.ts`                   |
| **A required variable missing** (`AUTH_SECRET`, `API_SHARED_SECRET`) | The API refuses every call with "The API is not configured."                                                                                               | `503 MISCONFIGURED`; System health shows Turnstile missing in production as an **Error**.                                                                                                                             | "missing configuration"                                              |
| **A migration fails half-way**                                       | Nothing changes for visitors.                                                                                                                              | The release stops before deploying the Worker; D1 applies each migration file as a whole. The runbook has the restore steps.                                                                                          | release preflight + `migration-lint.test.ts`                         |
| **Turnstile (bot check) unreachable**                                | Sign-in, sign-up and forms keep working.                                                                                                                   | The request is allowed under a strict extra limit (5 per address per hour); a token Turnstile says is invalid is still refused.                                                                                       | "bot protection unavailable"                                         |
| **Cloudflare analytics unavailable**                                 | System health shows "Unknown" for Cloudflare's figures; GUCC's own counts still show.                                                                      | The hourly free-tier guard falls back to GUCC's own (conservative) counts for storage and writes.                                                                                                                     | "analytics unavailable"                                              |
| **Two leaders act at once** (approve, publish, appoint)              | The second sees "This application was just approved by …".                                                                                                 | One change, one audit entry, one notification, one email: a guarded update plus an in-batch assertion aborts the loser's whole batch.                                                                                 | `transitions.test.ts`                                                |
| **A form saved over someone else's change**                          | "This was changed at … (last saved by …) after you opened it. Reload…"                                                                                     | Optimistic locking on posts, events, people, positions, roles, rules, committees, settings and quick edit.                                                                                                            | `optimistic-locking.test.ts`                                         |
| **A double click or retried request**                                | The same answer as the first time.                                                                                                                         | Idempotency keys replay the stored result for 10 s; a repeat while the first is running is told so; failures leave no key.                                                                                            | `edge-idempotency.test.ts`                                           |
| **A flood from one address**                                         | That address gets `429 Too many requests`.                                                                                                                 | In-memory per-address limits on `/media`, `/health` and uploads before any database work; repeat offenders of the D1 limits are refused from memory. The Vercel Firewall and Attack Mode sit in front of the website. | `edge-idempotency.test.ts`                                           |
| **Free storage or writes near the limit**                            | Uploads are paused with a clear message; everything else works.                                                                                            | The hourly guard switches `media.uploads_enabled` off at 90% and tells Moderators; caps are atomic.                                                                                                                   | `free-tier.test.ts`                                                  |

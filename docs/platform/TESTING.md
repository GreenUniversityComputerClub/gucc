## Running end-to-end tests

```bash
bun run test:e2e
```

The suite has its own database and never touches the one you develop on. `scripts/platform/e2e-prepare.ts`
rebuilds `.e2e/state` from scratch on every run (schema, the club's data) and clears the E2E build's
data cache. Playwright then starts its own API Worker on port 8788 (log in `.e2e/api-worker.log`) and
a production build of the website on port 3001 (built into `.next-e2e`). Your development servers on
8787 and 3000 can keep running.

Global setup creates the E2E Moderator (`moderator@local.test`) and clears rate-limit counters.
Development emails print to the Worker's log, where the tests read verification and invitation links.

The desktop story plays every level in turn:

1. A **public visitor** sees database content (including 2026's GUCC and CSS tabs); the admin redirects to login.
2. **Applicants** register and verify; pending members see "awaiting GUCC approval" and are kept out of the admin.
3. The **Moderator** approves them, ends the sitting President's term (kept in history) and appoints a new President through the Add executive dialog.
4. The **President** is refused self-assignment, appoints a Publication Secretary, and adds a brand-new Sports Secretary with an email invitation; the public committee page shows them.
5. The **invited executive** sets a password and has the position's access.
6. The **Publication Secretary's** post needs approval; the President approves; it goes live with the embedded script neutralised.
7. The President creates and activates a governance rule.
8. An image with EXIF is dropped into the uploader, goes straight to the Worker, and is stored as the library profile's WebP sizes (400, 800, 1280 and a 1920 px master) in the public bucket without metadata; re-uploading it is deduplicated.
9. Drafts are private; event registration fills capacity, waitlists, and rejects duplicates.
10. A **normal member** edits their profile but can't reach admin tools or moderation endpoints.
11. The Moderator reads the audit trail and sign-in activity, and suspends an account; its session stops working.

12. **Leadership tools** (`governance.spec.ts`): a JSON import with a duplicate and an unknown position is previewed, resolved and imported, and the people appear on the public committee page; two listings are ended with a bulk change; an administrator's one-time reset link lets a member set a password, once.

13. **Round 4** (`v4.spec.ts`): the navbar's Services menu opens Lost & Found; a leader gives a task and schedules a meeting with a Google Meet link, and the member sees both on their dashboard, finishes the task and replies to the meeting; a member turns on two-factor sign-in with a real authenticator code and then needs a code (or a recovery code) to sign in; a leader downloading the member list is asked to confirm their password first; the activity log and System health show real entries; executives quick edit and export; recruitment applications are imported from an Excel file after a preview; the home page figures are edited in a form and appear on the site.

14. **Role by role** (`roles.spec.ts`): a Moderator, the President, the General Secretary, a GUCC executive, a CSS executive, a Developer and a member each open the same dashboard pages; allowed ones render, the rest show "No access", and the navigation offers System health only to those who can open it; a President giving the Developer role waits for a Moderator's approval.

15. **Accessibility** (`a11y.spec.ts`): the axe WCAG 2.1 A/AA rules on the main public pages (without the colour-contrast rule, as the public design is fixed) and dashboard pages; serious or critical findings fail; the password eye shows and hides the password.

Also: every admin page renders (and the Content Security Policy blocks nothing on them); recruitment (campaign, applicant with private documents, signed links, shortlisting); contact → inbox; security probes (missing API key, cross-origin uploads, path traversal, CSRF, a real server action replayed from another origin refused with nothing changed, anonymous exports, revalidation, anonymous visitors never calling `/api/session`); SEO (unique titles, canonicals, valid JSON-LD, signed OG cards and the static card for made-up ones, sitemap without duplicates); and phones (no horizontal overflow on public and admin pages, working menu).

## Other checks (run by hand)

| Script                                                               | What it does                                                                                                                                                     |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `node scripts/qa/compare.mjs`                                        | Compares public pages on `http://localhost:3000` with the live site: text, links and layout height at 390 and 1280 px                                            |
| `node scripts/qa/theme-audit.mjs [url] [--dashboard email password]` | Day and night mode on every route at phone and desktop width: axe-core contrast, transparent menus and dialogs, sideways scrolling; screenshots in `.e2e/theme/` |
| `node scripts/qa/csp-check.mjs [url]`                                | Opens the public pages and lists anything the Content Security Policy blocked                                                                                    |
| `bunx playwright test -c scripts/qa/pw-reuse.config.ts <spec>`       | Re-runs one spec against E2E servers you already started on 8788 and 3001                                                                                        |
| `bun scripts/platform/lib/migration-lint.ts`                         | The release's migration safety lint, on the migrations not yet in production                                                                                     |
| `bun scripts/platform/restore-check.ts <dump.sql> [--compare local]` | Proves a database export restores: loads it into memory, runs integrity and foreign-key checks, compares row counts                                              |
